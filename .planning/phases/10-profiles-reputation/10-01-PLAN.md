# Phase 10 Plan 01: Profile Display & Own Profile View

**Goal:** Implement profile display pages for viewing user profiles (own and other users) with statistics, bio, location, and avatar display. This plan establishes the basic profile page structure, routing, and API integration.

## Dependencies

- **Phase 9 Plan 03:** Session & Logout (must be complete)
- **Available from Phase 9:** CSS component library, app.js router, localStorage auth, fetchAPI helper

## Requirements Addressed

- **FE-PROF-01:** Profile view page showing user stats (ratings, sales, listings)
- **FE-PROF-04:** User statistics dashboard (active listings, completed sales, avg rating)

## Implementation Summary

This plan creates a profile page that works for both own profile (#/profile) and other users' profiles (#/profile/123). The page structure includes:

1. Avatar display with initials fallback (from Phase 9 token system)
2. Profile header with name, bio, location
3. Stats grid showing 6 metrics (active listings, completed sales, average rating, member since, response time, total reviews)
4. Own profile shows edit button, other profiles show read-only view
5. Reviews section stub (filled by Plan 02)

## Tasks

### Task 1: Create profile page renderer with dual-mode view

**What:** Implement app.showProfile() function that:
- Reads userId from route parameter (#/profile or #/profile/123)
- Determines if viewing own profile (compare userId to app.user.id)
- Renders page layout with sections: avatar/header, stats, reviews placeholder
- Handles loading state while fetching data

**How:**
1. Add showProfile(userId) to app object in public/js/pages/profile.js
2. Extract userId from URL hash or use current user ID
3. Render profile header layout (avatar, name, bio, location, button bar)
4. Create profile stats structure (6 stat cards grid)
5. Stubbed reviews section (placeholder, filled by Plan 02)
6. Handle loading states with app.showLoading()

**Acceptance Criteria:**
- Page renders without errors when /api/v1/users/{userId} returns user data
- Avatar displays (placeholder while waiting for avatar upload implementation)
- Name, bio, location display correctly
- Stats grid shows 6 fields: Active Listings, Completed Sales, Average Rating, Member Since, Response Time, Total Reviews
- Edit button visible ONLY on own profile (#/profile without parameters)
- Read-only display on other users' profiles (#/profile/123)

---

### Task 2: Fetch profile data from backend API

**What:** Implement API integration to load user profile and statistics:
- GET /api/v1/users/{userId} - fetch user data
- Handle 404 (user not found), 401 (unauthorized), 500 (server error)
- Use app.apiCall() helper from Phase 9

**How:**
1. Create async loadUserProfile(userId) function
2. Call app.apiCall(`/api/v1/users/${userId}`)
3. Parse response: name, bio, location, email, created_at, avatar_url
4. Extract stats from response: listings_count, completed_sales, avg_rating, review_count
5. Cache in localStorage with 5-minute TTL (for repeated views)
6. Show error message if fetch fails

**Acceptance Criteria:**
- Profile data loads successfully for valid user IDs
- User not found (404) shows friendly error message
- Unauthorized (401) redirects to login
- Server errors (500) show retry prompt
- API calls include Authorization header (from Phase 9 app.apiCall)
- Loading state displays while fetching

### Task 3: Implement stats grid layout and styling

**What:** Create responsive stats card grid showing 6 metrics with Phase 9 component library

**How:**

2. Define .profile-stats-grid using CSS Grid (3 columns, gap 16px)

4. Define .stat-value (large font, color-primary) and .stat-label (small font, color-text-secondary)

**Acceptance Criteria:**

- Each stat card shows value (number) + label (text)

- Spacing consistent with Phase 9 token system (--space-16 gap)

### Task 4: Create avatar display with initials fallback

**What:** Render user avatar image or initials if no avatar uploaded yet

**How:**
1. Add renderAvatar(user) helper function in profile.js
2. If user.avatar_url exists, render `<img src="/api/v1/users/{userId}/avatar?size=200">`
3. If no avatar, render initials: extract first letter of first name + first letter of last name
4. Use deterministic color based on user ID: `hsl(${hash(userId) % 360}, 70%, 60%)`
5. Style as circular div with background color, centered text (white, bold)

**Acceptance Criteria:**
- Existing avatars display with correct image
- Missing avatars show 2-letter initials in colored circle
- Color is consistent for same user across app
- Avatar size 200px on profile page
- Background image loading state (spinner while downloading)

---

### Task 5: Update app.js router to support profile routes

**What:** Add profile routes to SPA router in app.js

**How:**
1. Update loadPage() function to handle:
   - #/profile → showProfile(app.user.id) - own profile (protected)
   - #/profile/{userId} → showProfile(userId) - other user profile (public)
2. Add 'profile' to protectedRoutes array
3. Extract userId from hash path using regex: `/#\/profile\/?(.*)/ `
4. Update sidebar menu to link to #/profile (own profile link)

**Acceptance Criteria:**
- #/profile route loads own profile (protected)
- #/profile/123 route loads user 123's profile (public)
- Accessing #/profile without auth redirects to login
- Sidebar "Profile" link goes to #/profile
- No console errors on route navigation

---

### Task 6: Implement profile header with name, bio, location

**What:** Render profile header section with user information

**How:**
1. Create .profile-header CSS class with flex layout
2. Layout: Avatar (left) | Name + Bio + Location (right) | Edit Button (if own profile)
3. Name: bold, --text-lg
4. Bio: --text-sm, --color-text-secondary, italic, max 3 lines
5. Location: --text-sm, with location icon (via CSS, no emoji)
6. Edit button: only visible if app.user.id === userId

**Acceptance Criteria:**
- Header displays avatar, name, bio, location in single row/section
- Edit button appears only on own profile
- Information displays correctly for both own and other users
- Responsive layout for v2.1 (stacking on mobile)
