# Phase 10 Plan 02: Profile Editing & Avatar Upload

**Goal:** Implement profile edit modal for own profile with name, bio, location editing and avatar upload functionality with preview and fallback handling.

## Dependencies

- **Phase 9 Plan 03:** Session & Logout (must be complete)
- **Phase 10 Plan 01:** Profile Display (profile.js file must exist)
- **Available from Phase 9:** Modal component library, form validation patterns, design tokens

## Requirements Addressed

- **FE-PROF-02:** Profile edit form (name, bio, location)
- **FE-PROF-03:** Avatar upload and display

## Implementation Summary

This plan adds modal-based editing to the profile page from Plan 01. When user clicks "Edit Profile" button on their own profile, a modal dialog opens with:

1. Editable form fields: name, bio, location (with client-side validation)
2. Avatar upload input with image preview
3. Cancel and Save buttons
4. Server-side error handling displayed inline
5. Loading state during upload
6. Success feedback and modal close on completion

## User Decision References

From CONTEXT.md:
- Modal dialog interface for editing (quick edits, clear cancel path)
- Client-side + server validation (prevent bad data client-side, handle business rules server-side)
- Display backend errors inline in form fields

## Tasks

### Task 1: Create profile edit modal structure in HTML

**What:** Add modal HTML to profile page for editing profile fields

**How:**
1. Create modal div (#profileEditModal) with Phase 9 modal structure:
   - modal-backdrop (clickable to close)
   - modal-content with modal-header, modal-body, modal-footer
2. modal-body contains form with fields:
   - Name (text input, required, 2-100 chars)
   - Bio (textarea, optional, max 500 chars)
   - Location (text input, optional, max 100 chars)
   - Avatar (file input, image only, max 5MB)
3. Error message placeholders for each field (inline, hidden by default)
4. modal-footer with Cancel and Save buttons
5. Avatar preview image placeholder

**Acceptance Criteria:**
- Modal hidden by default (display: none)
- Modal appears/disappears on button click
- Form has 4 input fields + 4 error message spans
- Phase 9 modal component classes used (.modal, .modal-backdrop, etc.)
- No inline styles (use CSS classes)

---

### Task 2: Implement profile edit modal show/hide logic

**What:** Add JavaScript functions to show/hide modal and populate form with current user data

**How:**
1. Create showEditProfileModal() function that:
   - Fetches current user data from app.user
   - Populates form fields: name, bio, location
   - Shows modal by setting display: block
   - Clears any previous error messages
   - Resets file input
2. Create hideEditProfileModal() function that:
   - Hides modal (display: none)
   - Clears form fields (optional, for privacy)
   - Clears error messages
3. Attach event listeners:
   - Edit button → showEditProfileModal()
   - Modal backdrop click → hideEditProfileModal()
   - Cancel button → hideEditProfileModal()
   - Escape key → hideEditProfileModal()

**Acceptance Criteria:**
- Modal appears when Edit button clicked
- Form pre-fills with current user name, bio, location
- Modal closes on backdrop click, Cancel button, or Escape
- Form clears on close (optional)
- No console errors on open/close

---

### Task 3: Implement client-side form validation with real-time feedback

**What:** Add field-level validation on blur and form-level validation on submit

**How:**
1. Create validateField(fieldId) function that validates:
   - name: required, 2-100 chars
   - bio: optional, max 500 chars
   - location: optional, max 100 chars
2. Add blur event listeners to form fields, call validateField on blur
3. Create validateForm() function that validates all fields
4. Display/clear error messages in real-time:
   - If invalid: add is-invalid class to input, show error text
   - If valid: remove is-invalid class, clear error text
5. Disable Save button if form invalid

**Acceptance Criteria:**
- Name field shows error if empty or outside 2-100 chars
- Bio field shows error if over 500 chars
- Location field shows error if over 100 chars
- Errors clear when field becomes valid
- Save button disabled if form invalid
- Error messages use Phase 9 .error-text class and --color-error token

---

### Task 4: Implement avatar file upload with preview

**What:** Handle file selection, preview, and validation before upload

**How:**
1. Add file input change listener that:
   - Validates file type (image/* only)
   - Validates file size (max 5MB)
   - Shows error if invalid
2. Create previewer:
   - Read file with FileReader.readAsDataURL()
   - Display preview in img element
   - Show preview while form open (help user verify crop)
3. Validation errors:
   - "Please select an image file" (wrong type)
   - "File must be less than 5MB" (too large)
   - Display in avatarError span element
4. Clear preview when modal closes

**Acceptance Criteria:**
- Only image files accepted (MIME type check)
- File size limited to 5MB
- Preview displays immediately when file selected
- Error messages show for invalid files
- File input can be cleared and changed
- Preview clears on modal close

---

### Task 5: Implement profile save with API call and error handling

**What:** Send profile updates to backend and handle responses

**How:**
1. Create saveProfile() function that:
   - Validates form client-side first
   - Collects form data: name, bio, location, avatar file (if provided)
   - Disables Save button during upload (loading state)
2. For text fields (name, bio, location):
   - POST /api/v1/users/me with JSON: { name, bio, location }
   - Include Authorization header via app.apiCall()
3. For avatar upload:
   - POST /api/v1/users/me/avatar with FormData (separate call if file selected)
   - Append file to FormData with key 'avatar'
   - Include Authorization header
4. Handle responses:
   - Success: hide modal, reload profile view, show success message
   - API errors: display inline errors in form (per field if provided)
   - Network errors: show generic error message
5. Handle loading state:
   - Disable Save button, show spinner
   - Re-enable on response (success or error)

**Acceptance Criteria:**
- Profile fields update successfully on backend
- Avatar uploads successfully if selected
- Form errors display inline (per-field if available)
- Server errors display in modal (not alert)
- Modal closes on successful save
- Profile view reloads with updated data
- Loading state prevents duplicate submissions

### Task 7: Handle inline form errors from backend

**What:** Display server validation errors in form fields (not alerts)

**How:**
1. After API response, check if response.ok
2. If error (response.errors object exists):
   - Parse response.errors: { name: "error message", bio: "..." }
   - For each error field:
     - Get error span element by ID: ${fieldId}Error
     - Set error text: errorSpan.textContent = message
     - Add is-invalid class to input
3. If generic error (no field errors):
   - Show in alert element (top of modal)
4. Clear field errors when user starts typing in that field

**Acceptance Criteria:**
- Server field errors display inline under each field
- is-invalid class applied to error fields
- Error text uses red color (--color-error)
- Errors clear on field change
- Generic errors show in alert at top of modal
