<objective>
Implement admin content moderation actions: hiding reported listings and banning problematic users. AdminService handles business logic; AdminController exposes HTTP endpoints; soft-delete columns (hidden_at, banned_at) control visibility without hard deletion.

Purpose: Enables admins to process reports by taking action on reported content. Hiding listings and banning users removes them from user-visible queries without destroying data (audit trail preserved). Connects reporting system (Plan 03) to actual moderation consequences.

Output: AdminService with 3 action methods, AdminController with 3 endpoints, soft-delete columns on listings/users tables
</objective>

# Architecture patterns
- Soft delete pattern: hidden_at and banned_at columns (nullable, set to NOW() when hidden/banned)
- Filtering: All queries include hidden_at IS NULL, banned_at IS NULL to exclude hidden/banned content
- Services: Authorization checks in service (admin role verification)
- Repositories: Additional columns tracked, filterable separately from deleted_at
</context>

<task type="auto">
  <name>Task 2: Create AdminService with action methods</name>
  <files>src/Services/AdminService.php</files>
  <action>
Create src/Services/AdminService.php with:

1. Constructor:
   - Inject: ListingRepository, UserRepository, ReportRepository
   - Store as private properties

2. hideContent(admin_id, reported_type, reported_id): PUBLIC
   - Validate: admin_id is valid UUID and has is_admin=true (authorization deferred to controller)
   - Validate: reported_type is 'listing' or 'user'
   - Validate: reported_id is valid UUID
   - If reported_type='listing': Call ListingRepository.hideListing(reported_id)
   - If reported_type='user': Call UserRepository.banUser(reported_id)
   - Return: {"action": "hidden", "reported_type": reported_type, "reported_id": reported_id}
   - Error handling: Throw InvalidArgumentException for validation errors

3. approveReport(admin_id, report_id): PUBLIC
   - Validate: admin_id is valid UUID
   - Validate: report_id is valid UUID
   - Find report via ReportRepository.findById(report_id)
   - Validate: report exists and status is 'pending'
   - Extract: reported_type and reported_id from report
   - Call: hideContent(admin_id, reported_type, reported_id)
   - Update report status to 'approved' via ReportRepository.updateStatus(report_id, 'approved')
   - Return: {"status": "approved", "action_taken": "hidden", "report_id": report_id}
   - Error handling: 404 if report not found, 422 if already approved/rejected

4. rejectReport(admin_id, report_id): PUBLIC
   - Validate: admin_id is valid UUID
   - Validate: report_id is valid UUID
   - Find report via ReportRepository.findById(report_id)
   - Validate: report exists and status is 'pending'
   - Update report status to 'rejected' via ReportRepository.updateStatus(report_id, 'rejected')
   - Return: {"status": "rejected", "report_id": report_id}
   - Error handling: Same as approveReport

5. getAdminStats(): PUBLIC (Admin only)
   - Count pending reports: ReportRepository.countByStatus('pending')
   - Count hidden listings: ListingRepository.countHiddenListings()
   - Count banned users: UserRepository.countBannedUsers()
   - Return: {"pending_reports": N, "hidden_listings": N, "banned_users": N}

6. Private helpers:
   - validateReportedType(type): Ensure 'listing' or 'user'
   - validateUUID(value): Ensure valid format
   - ensureReportPending(report): Check status is 'pending'

Security & Authorization:
   - Authorization check deferred to controller (admin role verification there)
   - Methods assume caller is authenticated admin (passed in admin_id)
   - Soft-delete preserves audit trail (no hard deletion)

<task type="auto">
  <name>Task 3: Create AdminController with moderation endpoints</name>
  <files>src/Controllers/AdminController.php</files>
  <action>
Create src/Controllers/AdminController.php with:

1. Constructor:
   - Inject: AdminService
   - Store as private property

2. getReports(Request $request): PUBLIC (Admin only)
   - Route: GET /api/admin/reports
   - Authorization: Check session user.is_admin == true, return 403 if not
   - Parse query: status ('pending'|'approved'|'rejected', default 'pending'), limit (default 20), offset (default 0)
   - Call: ReportService.getReportQueue(status, limit, offset) [from Plan 03]
   - Enrich: Add action buttons metadata to each report
   - Return: 200 with paginated list + action metadata
   - Error: 403 if not admin, 400 if bad query params

3. approveReport(Request $request): PUBLIC (Admin only)
   - Route: PATCH /api/admin/reports/:id/approve
   - Authorization: Check is_admin, return 403 if not
   - Extract: report_id from URL path
   - Extract: admin_id from session
   - Call: AdminService.approveReport(admin_id, report_id)
   - Return: 200 with {"status": "success", "data": {"status": "approved", "action": "hidden"}, "message": "Report approved and content hidden"}
   - Error: 403 if not admin, 404 if report not found, 422 if already approved

4. rejectReport(Request $request): PUBLIC (Admin only)
   - Route: PATCH /api/admin/reports/:id/reject
   - Authorization: Check is_admin, return 403 if not
   - Extract: report_id from URL path
   - Extract: admin_id from session
   - Call: AdminService.rejectReport(admin_id, report_id)
   - Return: 200 with {"status": "success", "data": {"status": "rejected"}, "message": "Report rejected"}
   - Error: Same as approveReport

5. getAdminStats(Request $request): PUBLIC (Admin only)
   - Route: GET /api/admin/stats
   - Authorization: Check is_admin, return 403 if not
   - Call: AdminService.getAdminStats()
   - Return: 200 with {"status": "success", "data": {"pending_reports": N, "hidden_listings": N, "banned_users": N}, "message": "Stats retrieved"}
   - Error: 403 if not admin

6. Private helpers:
   - validateAdminRole(user): Check is_admin, throw exception if false
   - extractReportIdFromPath(): Parse :id from URL
   - formatReportResponse(): Convert service response to API envelope

Endpoint Details:
- All endpoints check is_admin in controller (return 403 if not)
- Response envelope: {"status": "success"|"error", "data": {...}, "message": "..."}
- HTTP status: 200 (success), 400 (bad input), 403 (forbidden), 404 (not found), 422 (unprocessable)
- Action metadata includes button labels for frontend ("Approve", "Reject", "Delete")
