# Architecture patterns
- Response envelope: {"status": "success"|"error", "data": {...}, "message": "..."}
- Error types: InvalidArgumentException (400), AuthenticationException (401), AuthorizationException (403), NotFoundException (404), ConflictException (409), ValidationException (422)
- Validation: Inline errors with field names and constraints
- Performance: Index on hot query paths (user_id + created_at DESC, status + created_at DESC, etc.)
</context>

<task type="auto">
  <name>Task 1: Create ErrorHandler and ErrorHandlingMiddleware</name>
  <files>src/ErrorHandler.php, src/Middleware/ErrorHandlingMiddleware.php</files>
  <action>
1. Create src/ErrorHandler.php:
   - Static method formatError(Exception $e, int $statusCode = 500): array
     * Returns {"status": "error", "message": user-friendly string, "data": {...optional}}
     * Input: Exception object and HTTP status code
     * Maps exception types to status codes:
       - InvalidArgumentException → 400 Bad Request
       - NotFoundException → 404 Not Found
       - AuthenticationException → 401 Unauthorized
       - AuthorizationException → 403 Forbidden
       - ConflictException → 409 Conflict
       - ValidationException → 422 Unprocessable Entity
       - Generic Exception → 500 Internal Server Error
     * User-friendly messages (no stack traces, no SQL queries):
       - 400: "Invalid input: {field_name} must be {constraint}" (e.g., "Invalid input: listing_id must be a valid UUID")
       - 401: "You must log in to access this resource"
       - 403: "You do not have permission to perform this action"
       - 404: "Resource not found"
       - 409: "Conflict: {detail}" (e.g., "Conflict: This listing is already favorited")
       - 422: "Validation failed: {field}: {message}" for each field
       - 500: "An error occurred while processing your request. Please try again later."
     * Logging: Log full exception (with stack trace) server-side for debugging, but don't expose to client

   - Static method getStatusCode(Exception $e): int
     * Maps exception class to HTTP status code

   - Static method shouldExposeMessage(Exception $e): bool
     * Returns true for 4xx, false for 5xx (don't expose 500 details)

2. Create src/Middleware/ErrorHandlingMiddleware.php:
   - Wraps request/response handling in try/catch
   - Catches all exceptions at top level
   - Calls ErrorHandler.formatError()
   - Sets HTTP response status code and Content-Type: application/json
   - Returns JSON error response via response envelope
   - Logs exception with context (user_id, request path, query params) for debugging
   - Does NOT expose stack traces or sensitive data to client

Security:
   - 5xx errors: Generic message only, no details
   - 4xx errors: Specific but safe (don't reveal internal structure)
   - No SQL injection details exposed
   - No authentication bypass hints
  </action>

3. Query optimization guidelines:
   - All SELECT queries on paginated lists should use these indexes
   - No full table scans on large tables
