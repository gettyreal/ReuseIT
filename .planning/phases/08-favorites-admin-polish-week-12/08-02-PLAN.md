<task type="auto">
  <name>Task 1: Create FavoritesService with toggle, list, and validation logic</name>
  <files>src/Services/FavoritesService.php</files>
  <action>
Create src/Services/FavoritesService.php with:

1. Constructor:
   - Inject FavoriteRepository, ListingRepository, UserRepository
   - Store as private properties

2. toggleFavorite(user_id, listing_id): PUBLIC
   - Validate: user_id and listing_id are valid UUIDs
   - Validate: listing exists and is not deleted
   - Validate: listing.seller_id != user_id (can't favorite own listings)
   - Check if favorite exists via findByUserAndListing()
   - If exists AND deleted: restore (clear deleted_at) OR treat as idempotent no-op return "already favorited"
   - If exists AND not deleted: delete (soft-delete by setting deleted_at)
   - If not exists: create new favorite
   - Return: {"favorited": boolean, "message": string} indicating new state
   - Error handling: Throw InvalidArgumentException for invalid inputs, throw exception with user-friendly message if listing not found

3. getUserFavorites(user_id, limit=20, offset=0): PUBLIC
   - Validate: user_id is valid UUID
   - Fetch favorites via FavoriteRepository.findByUserId(user_id, limit, offset)
   - For each favorite: Load listing data via ListingRepository.find(listing_id)
   - Return: Array of favorite objects with enriched listing data (id, title, price, category, photo_url, seller info, created_at)
   - Order: created_at DESC (newest first)
   - Soft-delete filtering: Repository already handles; service just consumes

4. isFavorited(user_id, listing_id): PUBLIC
   - Check if favorite exists and not deleted
   - Return: boolean

5. Private validation helpers:
   - validateUUID(value): Throw InvalidArgumentException if invalid format
   - validateListingExists(listing_id): Query repository, throw if not found or deleted

Security & Validation:
   - Authorization: Only authenticated user can manage their own favorites (user_id must match session)
   - Idempotency: Toggle favorite twice = add then remove (no error on "already favorited")
   - Soft delete: Use soft-delete, not hard delete (allows historical tracking)

<task type="auto">
  <name>Task 2: Create ReportService with submission, validation, and admin methods</name>
  <files>src/Services/ReportService.php</files>
  <action>
Create src/Services/ReportService.php with:

1. Constructor:
   - Inject ReportRepository, ListingRepository, UserRepository
   - Store as private properties

2. submitReport(reporter_id, reported_type, reported_id, reason, comment=''): PUBLIC
   - Validate: reporter_id is valid UUID and authenticated
   - Validate: reported_type is 'listing' or 'user'
   - Validate: reported_id is valid UUID
   - Validate: reason is one of ['spam', 'fake', 'illegal', 'harmful']
   - Validate: comment is string, max 1000 characters
   - Check: if reported_type='user', reporter_id != reported_id (can't report self)
   - Check: if reported_type='listing', listing exists and not deleted
   - Check: if reported_type='user', user exists and not deleted
   - Prevent duplicates: Check if pending report already exists from same reporter on same content within 24 hours (no duplicate reports)
   - Create report via ReportRepository.create() with status='pending'
   - Return: {"report_id": id, "status": "pending", "message": "Report submitted successfully"}
   - Error handling: Throw InvalidArgumentException for validation errors with user-friendly messages

3. getReportQueue(status='pending', limit=20, offset=0): PUBLIC (Admin only)
   - Validate: status is 'pending', 'approved', or 'rejected'
   - Fetch reports via ReportRepository.findByStatus(status, limit, offset)
   - Enrich each report: Load reported listing/user data and reporter user data
   - Return: Array of enriched report objects with full context
   - Order: created_at DESC (newest first)
   - Note: Authorization check deferred to controller middleware

4. getReportsByContent(reported_type, reported_id): PUBLIC (Admin only)
   - Validate: reported_type is 'listing' or 'user'
   - Validate: reported_id is valid UUID
   - Fetch all reports (including soft-deleted) for this content
   - Enrich with reporter names and report details
   - Return: Array of reports for this specific listing/user
   - Sort: status='pending' first, then by created_at DESC

5. approveReport(report_id): PUBLIC (Admin only)
   - Validate: report exists and is 'pending'
   - Update status to 'approved' via ReportRepository.updateStatus()
   - Return: {"status": "approved", "message": "Report approved. Content will be hidden."}
   - Note: Actual content hiding deferred to Plan 04

6. rejectReport(report_id): PUBLIC (Admin only)
   - Validate: report exists and is 'pending'
   - Update status to 'rejected' via ReportRepository.updateStatus()
   - Return: {"status": "rejected", "message": "Report rejected."}

7. Private validation helpers:
   - validateReportedType(type): Ensure 'listing' or 'user'
   - validateReason(reason): Ensure one of ['spam', 'fake', 'illegal', 'harmful']
   - validateComment(comment): Ensure string, max 1000 chars
   - validateUUID(value): Throw InvalidArgumentException if invalid format

Security & Validation:
   - Authorization: Only admins can approve/reject; any user can submit (with rate limiting deferred to controller)
   - Duplicate prevention: Check 24-hour window to prevent spam report flooding
   - Self-reporting prevention: Can't report yourself
   - Input validation: All enums, UUIDs, text lengths validated before database mutation
