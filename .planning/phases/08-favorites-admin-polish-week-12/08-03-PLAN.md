   - Inject FavoritesService

2. toggleFavorite(Request $request): PUBLIC
   - Route: POST /api/listings/:id/favorite
   - Extract: listing_id from URL path parameter
   - Extract: user_id from authenticated session (via AuthMiddleware)
   - Call: FavoritesService.toggleFavorite(user_id, listing_id)
   - Return: 200 with {"status": "success", "data": {"favorited": boolean, "message": "..."}, "message": "Favorite toggled"}

     * 404 Not Found if listing doesn't exist
     * 422 Unprocessable Entity if validation fails (e.g., can't favorite own listing)

   - Route: GET /api/favorites
   - Extract: user_id from authenticated session
   - Parse query params: limit (default 20, max 100), offset (default 0)
   - Call: FavoritesService.getUserFavorites(user_id, limit, offset)
   - Return: 200 with {"status": "success", "data": [...favorites with listing details...], "pagination": {"limit": 20, "offset": 0, "total": N}, "message": "Favorites retrieved"}
   - Error handling:
     * 401 Unauthorized if not authenticated
     * 400 Bad Request if limit/offset invalid (non-numeric, negative)

4. Private helper:
   - extractListingIdFromPath(): Parse :id from URL (leverage existing Router path param extraction)
   - formatFavoriteResponse(): Convert FavoritesService response to API envelope

Endpoint Details:
- Both endpoints protected by AuthMiddleware (401 if not authenticated)
- Response envelope includes pagination metadata for getFavorites

<task type="auto">
  <name>Task 2: Create ReportController with submission and admin endpoints</name>
  <files>src/Controllers/ReportController.php</files>
  <action>
Create src/Controllers/ReportController.php with:

1. Constructor:
   - Inject ReportService
   - Store as private property

2. reportListing(Request $request): PUBLIC
   - Route: POST /api/listings/:id/report
   - Extract: listing_id from URL path parameter
   - Extract: user_id from authenticated session (via AuthMiddleware)
   - Parse request body: {"reason": "spam|fake|illegal|harmful", "comment": "optional text"}
   - Validate: reason and comment present and valid
   - Call: ReportService.submitReport(user_id, 'listing', listing_id, reason, comment)
   - Return: 201 Created with {"status": "success", "data": {"report_id": uuid, "status": "pending"}, "message": "Listing reported successfully"}
   - Error handling:
     * 400 Bad Request if listing_id invalid, reason invalid, comment too long
     * 401 Unauthorized if not authenticated
     * 404 Not Found if listing doesn't exist
     * 409 Conflict if duplicate report already submitted in past 24 hours

3. reportUser(Request $request): PUBLIC
   - Route: POST /api/users/:id/report
   - Extract: user_id from URL path parameter
   - Extract: authenticated user_id from session
   - Parse request body: {"reason": "spam|fake|illegal|harmful", "comment": "optional text"}
   - Call: ReportService.submitReport(authenticated_user_id, 'user', user_id, reason, comment)
   - Return: 201 Created with same format as reportListing
   - Error handling: Same as reportListing, plus 422 if trying to report self

4. getReports(Request $request): PUBLIC (Admin only)
   - Route: GET /api/admin/reports
   - Authentication: Check session user.is_admin == true, return 403 Forbidden if not admin
   - Parse query params: status ('pending'|'approved'|'rejected', default 'pending'), limit (default 20, max 100), offset (default 0)
   - Call: ReportService.getReportQueue(status, limit, offset)
   - Return: 200 with {"status": "success", "data": [reports with enriched data], "pagination": {...}, "message": "Reports retrieved"}
   - Error handling:
     * 403 Forbidden if not admin
     * 400 Bad Request if status/limit/offset invalid

5. Private helpers:
   - extractResourceIdFromPath(): Parse :id from URL
   - validateAdminRole(user): Check is_admin, throw exception if false
   - formatReportResponse(): Convert ReportService response to API envelope
   - parseRequestBody(): Extract JSON body parameters

Endpoint Details:
- reportListing and reportUser require authentication (AuthMiddleware)
- getReports requires admin role (checked in controller)
- All endpoints return consistent response envelope with error messages
- Status codes follow HTTP conventions (201 for creation, 403 for permission denied)
